# 界面文案规范

所有面向用户的文字都在 `app/src/i18n/zh-CN.ts`。组件里不写死中文。

这份文档是**怎么改**的规则，不是文案清单。改文案只动字典右边的值；键名要改就同步改组件里的引用，`pnpm build` 会告诉你漏了哪。

---

## 一、写之前先看这四个样本

改文案时手上应该有参照物。本项目的措辞基线来自两个同类产品的公开语言包（只看措辞规律，不搬代码、不搬句子）：

| 产品 | 文件 | 能学到什么 |
| --- | --- | --- |
| HMCL | `HMCL/src/main/resources/assets/lang/I18N_zh_Hans.properties` | 按钮 2–4 字；失败就写「X 失败」；空状态「没有 X」 |
| Modrinth App | `apps/app-frontend/src/locales/zh-CN/index.json` | 说明句只讲影响（`适用于中国大陆的镜像源`）；空状态「无安装任务」 |

对照它们最明显的一条：**成熟产品不自我介绍**。界面里几乎找不到产品名 + 「本工具会…」。界面只回答两件事——现在什么状态、我该点哪。

## 二、规则

### 1. 只写状态和动作

删掉「本工具会…」「这意味着…」「你可以通过…来…」。

| 别写 | 写 |
| --- | --- |
| 队列是空的。每装完一次，这一轮的文件数、体积和用时都会记在这里，可以随时回看。 | 无安装记录 |
| 引擎每一次安装推上来的进度、警告和错误都按时间落在这里。 | 安装过程中的进度、警告和错误。 |

### 2. 不挂解释性从句

「…，因为…」「…，而不是…」「…，同时…」一律删。除非不写会让用户做错事。

| 别写 | 写 |
| --- | --- |
| BMCLAPI 是社区维护的第三方镜像，不是 Mojang 官方服务器。 | 社区镜像，非 Mojang 官方。 |
| 镜像仅用于依赖库、资源文件和游戏本体；版本清单与版本 JSON 仍走官方。 | 仅加速依赖库、资源和本体。 |

### 3. 同一件事只说一遍

页头、提示、按钮三处都在说同一句，留一处。典型是「演示数据」：页头一句、提示一句、每行再一句，只留提示那一句。

### 4. 按钮写动词，2–4 字

| 别写 | 写 |
| --- | --- |
| 点击此处以开始安装 | 开始安装 |
| 下载并打开官方安装器 | 下载并打开 |
| 清除本机设置（危险操作区，允许说清范围） | 清除本机设置 |

### 5. 标题写名词

`已装版本`、`下载源`、`目标目录`。不写「这里是你的已装版本」，也不写成问句（`装到哪` → `目标目录`）。

### 6. 提示只写用户不知道的事

留下真事实，删掉显然的。

- 留：`隔离后的模组只有 PCL / HMCL 这类启动器读得到。官方启动器只读根目录 mods/。`
- 留：`游戏能启动，但没有音效和语言文件。`
- 删：`装完就能玩。`

### 7. 失败信息 = 发生了什么 + 下一步

两者都短。没有下一步就只写发生了什么。

| 别写 | 写 |
| --- | --- |
| 请选择游戏目录，或点「默认目录」使用系统 .minecraft。（界面里根本没有「默认目录」按钮） | 还没有选择游戏目录。 |
| 取不到版本列表，会装最新版。 | 无法获取版本列表，使用最新版。 |

### 8. 空状态用「无 X」/「没有 X」

| 别写 | 写 |
| --- | --- |
| 还没有开始安装。左边选好版本和加载器，点「开始安装」，这里会出现下载速度、本阶段剩余时间，以及每个阶段的文件数和字节数。 | 无安装任务。选好版本后点「开始安装」。 |
| 这个目录里还没有任何版本。回到「安装」页选一个版本开始，装完之后它会出现在这里。 | 没有版本。到「安装」页装一个。 |

### 9. 其他硬性约束

- 一句话 ≤ 40 个汉字，超了拆或删。
- 不用「请注意」「建议您」「不妨」「值得一提的是」。
- 不用感叹号，不用「哦」「啦」。
- 省略号用中文 `……`，不用 `…`。
- 标签末尾不加句号；整句说明加句号。
- 状态词统一：`安装中` / `完成` / `失败` / `已取消`（放 `common`，别各写一份）。
- 路径占位统一：`versions/<版本id>/mods/`。

## 三、键名与结构

```ts
T.InstallForm.versionLabel      // 语义名，不是 s12
T.QueuePanel.files(12)          // 带变量 → 字典里写成函数
T.common.statusCancelled        // 跨组件复用的短词放 common
```

- **按组件/页面分组**，组名 = 文件名去掉 `.tsx`。
- **跨组件复用的短词进 `common`**（`原版`、`状态`、`取消`、`打开目录`…），不要在五个页面里各写一遍。
- **带变量的写成函数**，调用方传值，不要在组件里拼字符串。目前 48 条是函数。
- 不用 `t('a.b.c')` 字符串路径：键名拼错要能在编译期报错。

改完必须 `cd app && pnpm build`。

## 四、改过的典型例子

以下是这次重写里最能说明问题的 14 条。左边是原来的线上文案，右边是现在的。

### 1. 空状态：三句变一句

- 原：`还没有开始安装。左边选好版本和加载器，点「开始安装」，这里会出现下载速度、本阶段剩余时间，以及每个阶段的文件数和字节数。`
- 新：`无安装任务。选好版本后点「开始安装」。`

### 2. 空状态：删掉「可以随时回看」

- 原：`队列是空的。每装完一次，这一轮的文件数、体积和用时都会记在这里，可以随时回看。`
- 新：`无安装记录`

### 3. 空状态：删掉操作教程

- 原：`这个目录里还没有任何版本。回到「安装」页选一个版本开始，装完之后它会出现在这里。`
- 新：`没有版本。到「安装」页装一个。`

### 4. 说明书式的提示

- 原：`最多显示 20 个版本，从新到旧。选「最新版」即可。`
- 新：`最多 20 个版本。`

### 5. 自我介绍句（最典型的一条）

- 原：`MCDL 只负责把模组装到对的位置，不启动游戏，也不改启动器的行为。已经装好的版本不会自动迁移：想换落点，重新装一次那个整合包最稳。`
- 新：`不启动游戏，也不改启动器。已装好的版本不会自动迁移。`

### 6. 一句里塞了三个事实

- 原：`镜像仅用于依赖库、资源文件和游戏本体；版本清单与版本 JSON 仍走官方。`
- 新：`仅加速依赖库、资源和本体。`

### 7. 社区来源说了一整句

- 原：`BMCLAPI 是社区维护的第三方镜像，不是 Mojang 官方服务器。`
- 新：`社区镜像，非 Mojang 官方。`

### 8. 按钮太长

- 原：`下载并打开官方安装器`
- 新：`下载并打开`

### 9. 错误信息引用了不存在的按钮

- 原：`请选择游戏目录，或点「默认目录」使用系统 .minecraft。`
- 新：`还没有选择游戏目录。`

### 10. 演示提示：两句变一句

- 原：`浏览器预览：搜索和进度来自内置的演示数据，不是真实网络。装成桌面应用后，这里会真的去 Modrinth / CurseForge 拉数据，并调用引擎下载。`
- 新：`浏览器预览：搜索和进度为演示数据。`

### 11. **内容已经错了**的旧文案（不只是啰嗦）

- 原：`MCDL 没有实例隔离：整合包会装进同一个 .minecraft 的 mods/ 里。同一个目录里再装第二个整合包，两边的模组会混在一起，所以换包之前最好换一个目录。`
- 新：`隔离开时模组进版本目录，关时进根 mods/，会和别的包混。`

项目后来加了版本隔离且默认开启，旧文案还在说「没有实例隔离」，属于会误导用户的错误信息。

### 12. 日志页整段说明

- 原：`引擎每一次安装推上来的进度、警告和错误都按时间落在这里。警告和错误前面有一块黄色标记，红色只用来表示删除。`
- 新：`安装过程中的进度、警告和错误。`

（后半句是设计规范，属于 `docs/UI.md` 的内容，不该出现在界面上。）

### 13. 扫描空状态：删掉猜测

- 原：`本机没有扫到可以导入的东西。常见原因：这台机器上只装过 MCDL 自己，或者其它启动器把游戏目录放在了非默认位置。下面的「扫描明细」会逐条说明每个位置为什么没找到。`
- 新：`没有找到可导入的实例。原因见下方「扫描明细」。`

### 14. Java 探测：主语从产品换成用户视角

- 原：`本机没找到 Java。安装时会按版本需要从 Adoptium 取一份，放在游戏目录的 runtime 下。`
- 新：`没有合适的 Java。安装时自动下载。`

## 五、哪些中文故意留在代码里

`zh-CN.ts` 之外还有 43 行中文，全部属于以下两类，**不是漏改**：

1. **浏览器演示后端的假数据**（`lib/packs-api.ts`、`lib/import-api.ts`、`lib/extras-api.ts`）
   - 例如假整合包的简介、扫描证据、`（演示）已放入 mods/…` 这类结果消息。
   - 它们会随演示后端一起删掉，界面上也已经标了「演示数据」。
2. **`lib/isolate.ts` 里 `selfCheck()` 的断言标签**（`开·路径`、`关·相对位置`…）
   - 开发者自检用，`selfCheck()` 不抛错就不显示。

新增界面文案时不要往这两类里塞。

## 六、加一条新文案

```ts
// 1. app/src/i18n/zh-CN.ts，找到对应组件组
InstallForm: {
  // ...
  submit: '开始安装',
},

// 2. 组件里
import { T } from '../i18n';
<button type="submit">{T.InstallForm.submit}</button>
```

跨组件的短词先看 `common` 有没有。带变量的在字典里写函数，签名要标类型：

```ts
files: (n: string) => `${n} 个文件`,
```

`app/src/i18n/index.ts` 目前只有中文；加语言时在那里加一张表，把 `T` 换成按设置返回的函数。
