# 文案与 i18n

所有面向用户的文字都集中在 **`app/src/i18n/zh-CN.ts`**，组件里不写死中文。

## 怎么用

```ts
import { T } from '../i18n';

<button>{T.installForm.s6}</button>
```

直接引用对象属性，而不是 `t('a.b.c')` 字符串路径：键名拼错会在 **编译期** 报错，
不用等到界面上出现一行 `undefined`。

带变量的文案写成函数，不要写 `{0}` 占位符：

```ts
// zh-CN.ts
installed: (n: number) => `已装 ${n} 个版本`,
// 组件
{T.versionsPage.installed(items.length)}
```

## 文件结构

字典按**源文件**分组，组名就是文件名（`InstallForm` / `SettingsPage` / `nav` …）。
每条后面带 `// L行号`，标注它在组件里的位置，方便对照。

键名 `sN` 是抽取时按行号顺序编的号，**只保证稳定，不表达语义**。
改文案时只改右边的值；想改成语义键名（`title` / `lede` / `emptyHint`）也可以，
但组件里的引用要跟着改。

## 加一种语言

1. 复制 `zh-CN.ts` 为 `en-US.ts`，翻译值；
2. 在 `i18n/index.ts` 里把 `T` 从常量改成按设置返回的函数；
3. 语言设置存在 `lib/settings.ts` 里，和 `concurrency` 一样持久化。

在那之前 `T` 是一个常量对象，没有运行时开销，也没有加载成本。

## 重新盘点文案

```bash
python scripts/extract-i18n.py
```

它会扫描 `app/src` 下的组件，把中文抽出来重写成 `zh-CN.ts`。

⚠️ 这个脚本是**生成骨架**用的，会覆盖现有文件。已经手工改过文案之后就别再跑了，
否则你的修改会被线上文案盖掉。

## 写作约定

- 一句话只说一件事；
- 按钮写动作（「保存」「删除这条记录」），标题写内容（「本月订单」），不写风格词；
- 出错时说清**发生了什么**和**下一步能做什么**，不要只说「操作失败」；
- 数字、版本号、路径不翻译。
